# DSH Web Search Billing

**简体中文** · [English](./README.en.md)

为 DSH 的原生 `web_search` / `web_fetch` 管理搜索渠道、API Key 和本地费用账本。

同一套 DSH 中，官方 API、中转和其他搜索服务可以分别配置、分别计量。Search 与 Fetch 各走各的渠道；失败时可按您指定的顺序切换，而不是直接改走一个未知价格的服务。

> 当前版本 **0.5.1**，兼容基线 **DSH 0.2.1-rc.2**。费用是本插件可观测请求的**本地估算**，不是服务商账单，也不是模型 Token 费用统计。

## 能做什么

- **按 Provider 路由**：搜索渠道跟随发起请求的模型 Provider ID；Search、Fetch 独立绑定，支持全局和会话级覆盖。
- **分渠道核算**：官方和中转使用各自的单价、币种与计费策略；按日期、渠道、来源 Provider、会话和币种筛选。
- **多渠道接力**：显式开启后，缺 Key 的引擎跳过，失败、限流或超时按配置顺序切换；成功或合法空搜索结果停止接力。
- **多 Key 池**：界面中每行填写一个 Key，顺序轮换起点；失败时先尝试本渠道的其他 Key，再决定是否切换渠道。
- **逐 Key 测试**：选择 Search 或 Fetch，确认费用风险后测试本次输入或已保存池，显示脱敏结果；不自动保存输入，不转投其他渠道。
- **本地持久账本**：每次实际尝试独立记录，接力请求通过 `operationId` 关联；历史价格保留快照，改价不会重算过去的账目。
- **完整配置界面**：渠道管理、Provider 与覆盖、用量与费用三个面板；支持深色、窄面板、键盘下拉操作及长列表窗口化。

## 与只做搜索接入的工具有什么不同

本插件的重点不是再增加一个搜索按钮，而是把**路由、可用性和费用证据**放在一起。下表说明设计取舍，不是对特定第三方插件的实测排名。

| 您遇到的问题 | 本插件的处理方式 | 实际价值 |
| --- | --- | --- |
| 官方和中转都叫 DeepSeek，但价格不同 | 分开建渠道、绑定 Provider、保存价格快照 | 不会把中转调用混入官方费用 |
| 搜索要走 API，抓取想走本地 HTTP | Search / Fetch 独立绑定与覆盖 | 不必为了一个操作更换整套搜索方案 |
| 一个 Key 限流，或者一个服务超时 | 渠道内 Key 接力，再按显式开关跨渠道接力 | 控制切换顺序和等待预算，而非无条件重试 |
| 前一个请求超时，后一个成功，费用怎么算 | 每次实际尝试单独落账；不确定结果单独标记 | 不会因为最终成功就抹掉前面的尝试 |
| 价格未知，页面却看起来像免费 | 未知价格、未确认结果与已知金额分开显示 | 已知费用不会被误读成完整账单 |
| 不想为了填写 Key 修改配置文件 | 直接输入私有 Key 池，界面不读回旧 Key | 配置更直接，也不覆盖模型的同名凭证 |

**适合**在多个模型 Provider、官方 API、中转和搜索服务之间分配流量、排查调用和估算成本的 DSH 用户。

**不适合**把它当作全账户账单同步、自动选择最便宜服务或无限免费搜索工具。它不会枚举公共搜索实例，也不会静默启用收费接力。

## 支持的渠道

| 渠道 | Search | Fetch | 说明 |
| --- | :---: | :---: | --- |
| DeepSeek 官方 API | ✓ | ✓ | 两种操作独立估价 |
| DeepSeek 兼容中转 | ✓ | ✓ | 需要兼容工具 API 协议，不能只支持聊天接口 |
| TinyFish | ✓ | ✓ | 使用各操作对应的官方 API 地址 |
| 百度千帆 | ✓ | — | 仅搜索，不会出现在 Fetch 绑定中 |
| Tavily | ✓ | ✓ | basic Search / Extract；credits 是本地保守预留 |
| SearXNG | ✓ | — | 自建或获准使用的实例，需要开放 JSON 格式 |
| 本地 HTTP | — | ✓ | 复用 DSH 抓取后端，无本插件按次 API 费用 |

服务商价格、免费额度和访问限制以其账户计划为准。SearXNG 与本地抓取仍有部署、网络和目标站点访问成本；插件不承诺第三方服务免费或无限量。

## 安装

### 1. 从源码构建

要求 Node.js **≥22.19**，目标 DSH 为 **0.2.1-rc.2**。其他 DSH 版本尚未验证，不建议绕过兼容检查强装。

```powershell
pnpm install --frozen-lockfile --ignore-scripts
node scripts/check.mjs
npm pack --ignore-scripts
```

生成 `dsh-web-search-billing-0.5.1.tgz`。当前不以 npm 在线发布作为安装前提。

### 2. 安装到目标 Profile

**先完全退出使用目标 DSH_HOME 的 DSH 进程**，并备份现有 Profile 与插件数据，再安装：

```powershell
dsh plugin --profile web add "./dsh-web-search-billing-0.5.1.tgz" --ignore-scripts
```

将 `web` 换成实际 Profile。Windows 桌面版可使用仓库提供的安装入口，显式调用桌面内置 pnpm，避免与全局 pnpm/store 版本冲突：

```powershell
# 安装目录与脚本默认值不同时，先设置为本机真实路径。
$env:DSH_DESKTOP_APP_ROOT = "C:/path/to/DSH Desktop/resources/app"
node ./scripts/desktop-cli.mjs plugin --profile desktop add "./dsh-web-search-billing-0.5.1.tgz" --ignore-scripts
```

上述路径需要自行替换。脚本不修改全局 pnpm/store 配置，默认保留依赖发布时间保护。遇到 `minimumReleaseAge` 拒绝时，优先等待或检查依赖，不要直接删除锁文件或全局关闭保护。

更新时同样先退出 DSH，再安装新包。不要在同一 Profile 混用源码目录 link 与 tgz 安装。

## 第一次配置

1. 重启 DSH，进入设置侧边栏的 **搜索渠道与费用**。
2. 在 **渠道管理** 中添加渠道，填写名称、地址和费率，先保存渠道配置。新建渠道默认停用，不会自动发请求。
3. 在渠道的 **API Key** 区域每行输入一个 Key，保存 Key 池。再次保存是**替换整个池**，不是追加；已保存的 Key 不回显。
4. 在 **渠道地址、费率与高级配置** 中勾选“启用”，保存渠道配置。**保存 Key 不等于启用渠道。**
5. 在 **Provider 与覆盖** 中，为实际模型 Provider ID 分别选择 Search、Fetch 渠道并保存。优先级为：**会话覆盖 → 全局覆盖 → Provider 绑定**。
6. 确认宿主 Web 工具后端为 `web-search-metered` / `web-fetch-metered`。安装 patch 会设置这两个后端，但其他更高优先级配置可能覆盖它们。
7. 发起一次原生调用，在 **用量与费用** 查看最近记录。需要接力时，再显式开启对应操作的“有序切换”，调整渠道顺序和超时预算。

安装后不默认绑定模型 Provider，也不会静默选择收费渠道。配置示例见 [provider-routing.patch.yml](./examples/provider-routing.patch.yml)，其中的 Provider ID、地址和费率需按实际情况修改。

### Key 测试

输入框有内容时测试本次输入；为空时测试已保存池或兼容凭证引用。每个 Key 只尝试一次，单 Key 最多 10 秒、整批最多 60 秒；不切换渠道，也不自动保存。测试后输入保留，方便确认后保存。

**测试可能收费，并会计入账本。** Fetch 使用固定目标 `https://example.com/`。超时、限流或网络错误不等于 Key 无效，也不能证明服务商未扣费。正常请求的 Key 轮换游标仅在当前进程内共享，重启后重置；最多支持 32 个 Key。

## 如何计算费用

账本区分计费成功、空结果、明确失败、未确认和未知价格。统计单位是**实际 API 尝试**，不是聊天轮数；一个含多个查询的工具调用可能产生多次底层请求。

- DeepSeek 官方预置价格为 Search / Fetch 各 **5 CNY／千次**，这是当前插件默认配置，不是实时价格同步。默认策略按 HTTP 200 且结果非空确认计费。
- 中转独立配置单价，可选择非空成功或所有 HTTP 200 计费；是否与服务商实际口径一致，需要自行核对。
- 例如 `5／千次 × 10 次计费成功 = 0.05`。内部使用整数微单位累加，CNY、USD 分开显示，不自动换汇。
- 派发后的超时、断连或无法解析的响应可能记为未确认；后续接力成功不会删除这些记录。未知价格不按零处理。
- 只统计经过本插件后端的请求，不能补记未被观测的历史，也不覆盖其他插件、设备或模型服务端内部搜索。

Tavily credits 保护只覆盖本插件能观察到的使用，不能保证账户不超支。同一 DSH_HOME 下，相同 Key 在不同渠道/Profile 间共享本地额度；其他设备、工具或 DSH_HOME 的消耗不在保护范围内。

## 数据与安全边界

- Key 池交给宿主凭据存储，按 DSH_HOME、Profile 和渠道隔离，不写入插件配置或账本，不覆盖模型的同名凭证。**宿主默认本地存储不等于加密保险箱。**
- 账本不保存 Key、Authorization、查询词或网页正文；保存渠道身份、请求归属、时间、状态和价格等计量信息。
- 数据位于 `$DSH_HOME/web-search-billing/`。备份时停止共享该目录的进程，并一起保留数据库及其相关文件、`installation-salt`，不要只复制正在写入的主数据库。
- 已有历史账目的渠道**仍可正常使用**，只是不能删除或更换地址归属。要换服务请新建渠道；不用时可停用。改名或改价不重算历史。
- 旧账本升级会先做一致性备份；失败不会自动删除账本。不要在同一数据目录混跑新旧版本，也不要只降数据库版本号来回退。

## 常见问题

**已保存千帆，为什么不能选？** 先在渠道高级配置中启用并保存。停用渠道会显示原因但不可选；千帆只能用于 Search。

**发起了搜索，为什么没有费用？** 检查宿主后端选择、Provider 绑定、Key 与渠道启用状态，以及用量页的日期和币种筛选。配置就绪不代表请求成功；未经过本插件的请求不会入账。

**已有请求记录，是不是渠道不能用了？** 不是。这是历史账目保护，不是连通性检测或停用操作；启用且凭据/路由有效即可继续使用。

**卸载会清空账本吗？** 不会。退出 DSH 后运行 `dsh plugin --profile web remove dsh-web-search-billing`，将 Profile 名替换为实际值。卸载不自动擦除历史数据。
