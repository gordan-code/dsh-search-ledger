# DSH Web Search Billing

**简体中文** · [English](./README.en.md)

DSH 原生 `web_search` / `web_fetch` 的渠道管理和费用统计插件。

在 DSH 里同时用 DeepSeek 官方 API、中转和其他搜索服务时，搜索该走哪个渠道、失败后换谁、用了多少次，都需要分开配置和查看。这个插件把这些事放到一个页面里：按模型 Provider 绑定搜索渠道，管理每个渠道的 Key，再用本地账本记录实际请求。

当前版本为 **0.5.1**，适配 **DSH 0.2.1-rc.2**。它统计的是经过插件的搜索和抓取请求，不是模型 Token 用量；显示的费用是本地估算，不能代替服务商账单。

## 功能

- Search 和 Fetch 可以选不同渠道，也可以按 Provider、全局或会话单独覆盖。
- 官方 API 和中转分别设置价格、币种及计费方式，不把它们混在一起算。
- 一个渠道可以保存多个 Key，每行一个。正常请求轮换起点，遇到失败先尝试同渠道的其他 Key。
- 可以开启有序切换。缺 Key 的引擎直接跳过，失败、限流或超时后按配置顺序尝试下一个渠道；成功或合法的空搜索结果会停止切换。
- 每次实际尝试都会单独记账。同一轮切换通过 `operationId` 关联，历史记录使用请求当时的价格，不会随当前配置重新计算。
- 用量可以按日期、渠道、来源 Provider、会话和币种筛选。界面支持深色、窄面板、键盘操作和长下拉列表。

Key 可以直接在界面填写，也可以逐个测试。测试需要先确认费用风险，不会自动保存输入或切换到别的渠道。

## 和只接入搜索 API 的插件有什么区别

这里多做的一层，是把请求路由和费用记录连起来。

例如，官方 DeepSeek Provider 的 Search 走官方 API，中转 Provider 的 Search 走中转，Fetch 则统一走本地 HTTP。三者可以各用各的价格和凭据，不必为了换一个操作而更换整套搜索配置。

失败后的账目也会保留。第一个渠道超时，第二个成功，不意味着只发生过一次请求。插件会留下前一次尝试，并把无法确认的结果单独标出来。价格没填时显示未知，不会因为金额暂时算不出来就显示成免费。

如果需要在多个 Provider 和搜索服务之间分配请求，或者想查清一次调用走了哪里、费用为什么增加，这些记录会比较有用。它不做全账户账单同步，也不会自动挑选最便宜的服务、搜集公共搜索实例或悄悄启用收费接力。这里介绍的是本插件的做法，不是对某个第三方插件的测试结论。

## 支持的渠道

| 渠道 | Search | Fetch | 备注 |
| --- | :---: | :---: | --- |
| DeepSeek 官方 API | ✓ | ✓ | Search、Fetch 分别计价 |
| DeepSeek 兼容中转 | ✓ | ✓ | 需要兼容工具 API，只支持聊天接口不够 |
| TinyFish | ✓ | ✓ | 使用对应操作的官方 API 地址 |
| 百度千帆 | ✓ | — | 只支持 Search |
| Tavily | ✓ | ✓ | basic Search / Extract；credits 在本地保守预留 |
| SearXNG | ✓ | — | 自建或获准使用的实例，需要启用 JSON 输出 |
| 本地 HTTP | — | ✓ | 复用 DSH 抓取后端，没有本插件按次收取的 API 费用 |

是否免费、能用多少次，要看服务商的账户计划。SearXNG 和本地抓取也有部署、网络及目标站点访问成本，不代表无限免费。

## 安装

需要 Node.js **≥22.19** 和 **DSH 0.2.1-rc.2**。其他 DSH 版本还没有验证，不建议跳过兼容检查强行安装。

### 从源码构建

在仓库目录运行：

```powershell
pnpm install --frozen-lockfile --ignore-scripts
node scripts/check.mjs
npm pack --ignore-scripts
```

会生成 `dsh-web-search-billing-0.5.1.tgz`，可以直接用本地包安装，不依赖 npm 在线发布。

### 安装到 DSH

先备份目标 Profile 和插件数据，完全退出共享该 DSH_HOME 的 DSH 进程，再执行：

```powershell
dsh plugin --profile web add "./dsh-web-search-billing-0.5.1.tgz" --ignore-scripts
```

把 `web` 换成实际使用的 Profile 名称。

Windows 桌面版可以用仓库里的安装脚本。它调用桌面自带的 pnpm，避免全局 pnpm 和桌面依赖使用不同 store 版本：

```powershell
# 如果与脚本默认安装位置不同，先填本机实际路径。
$env:DSH_DESKTOP_APP_ROOT = "C:/path/to/DSH Desktop/resources/app"
node ./scripts/desktop-cli.mjs plugin --profile desktop add "./dsh-web-search-billing-0.5.1.tgz" --ignore-scripts
```

示例路径需要替换。脚本不会改全局 pnpm/store 配置，默认也不会关闭依赖发布时间检查。遇到 `minimumReleaseAge` 拒绝时，先检查依赖或等待版本满足时间要求，不要直接删除锁文件或全局关闭保护。

更新也是先退出 DSH，再安装新包。同一个 Profile 不要混用源码目录 link 和 tgz 安装。

## 配置

重启 DSH 后，在设置侧边栏打开 **搜索渠道与费用**，按下面的顺序配置：

1. 在 **渠道管理** 添加渠道，填写名称、地址和费率，保存渠道配置。新建渠道默认停用，不会自动发送请求。
2. 展开渠道，在 **API Key** 区域每行输入一个 Key，保存 Key 池。之后再次保存会替换整个池，不是追加。已经保存的 Key 不会显示出来。
3. 在 **渠道地址、费率与高级配置** 勾选“启用”，再保存渠道配置。保存 Key 和启用渠道是两件事。
4. 到 **Provider 与覆盖**，为实际的模型 Provider ID 分别选择 Search、Fetch 渠道并保存。覆盖顺序是：会话覆盖 → 全局覆盖 → Provider 绑定。
5. 确认宿主 Web 工具使用 `web-search-metered` / `web-fetch-metered` 后端，发起一次原生调用，再去 **用量与费用** 看最近记录。

安装 patch 会选择这两个后端，但其他更高优先级的配置可能覆盖它。插件不默认绑定模型 Provider，也不会在没有绑定时自行选择收费渠道。

需要自动切换时，在对应操作下打开“有序切换”，调整渠道顺序和超时预算。配置示例在 [provider-routing.patch.yml](./examples/provider-routing.patch.yml)，其中的 Provider ID、地址和价格都需要按实际情况修改。

### 测试 Key

选择 Search 或 Fetch，再点击“测试 Key”。输入框有内容时测本次输入，为空时测已保存池或兼容凭证引用。测试后输入会保留，需要自己点保存。

每个 Key 只试一次，单 Key 最多 10 秒，整批最多 60 秒。测试不切换渠道，但**可能收费，也会写入账本**。Fetch 的测试目标固定为 `https://example.com/`。超时、限流和网络错误不一定是 Key 无效，也不能说明服务商没有扣费。

Key 池最多支持 32 个 Key。正常请求的轮换游标在当前进程内共享，重启后重置。

## 费用怎么算

统计单位是实际 API 尝试，不是聊天轮数。一次工具调用里有多个查询时，可能发送多次底层请求。

DeepSeek 官方渠道默认给 Search 和 Fetch 各设置 **5 CNY／千次**，按 HTTP 200 且结果非空确认计费。这是插件的默认配置，不会实时同步服务商价格。中转可以独立填写单价，选择非空成功或所有 HTTP 200 计费，具体口径要自己与服务商核对。

例如，单价 5 元／千次，10 次计费成功就是 0.05 元。金额在内部用整数微单位累加，CNY 和 USD 分开显示，不自动换汇。

账本会分别显示计费成功、空结果、明确失败、未确认和未知价格。请求发出后超时、断连或响应无法解析时，可能无法确认服务端是否计费，因此不会直接按免费处理。后续切换成功，也不会删掉前面的尝试。

插件只能记录经过自己后端的请求。其他插件、设备、模型服务端内部搜索，以及安装前没有被观测到的调用，都不在统计范围内。

Tavily 的 credits 也只是本地保护。同一 DSH_HOME 下，相同 Key 在不同渠道和 Profile 间共享本地额度；其他工具、设备或 DSH_HOME 的消耗无法统计，不能据此保证整个账户不超支。

## 数据和备份

Key 池保存在宿主凭据存储中，按 DSH_HOME、Profile 和渠道隔离，不写进插件配置或账本，也不覆盖模型的同名凭证。宿主默认的本地存储不是加密保险箱，仍然需要保护本机账户和文件。

账本不保存 Key、Authorization、查询词或网页正文，只保留渠道身份、请求归属、时间、状态和价格等计量信息。数据目录是 `$DSH_HOME/web-search-billing/`。

备份前停掉共享该目录的进程，把数据库及其相关文件和 `installation-salt` 一起保留。不要只复制正在写入的主数据库。旧账本升级前会先做一致性备份；失败不会自动删除账本。也不要在同一目录混跑新旧版本，或只修改数据库版本号来回退。

有历史账目的渠道仍能正常使用，只是不能删除或更换地址归属。要换服务就新建渠道，不再用的可以停用。修改名称或价格不会重算历史账目。

## 常见问题

### 渠道已经保存，为什么还是不能选？

先到渠道高级配置里勾选“启用”并保存。停用渠道会列出原因，但不能选择。千帆只支持 Search，不会出现在 Fetch 下拉框里。

### 搜索过了，为什么用量是空的？

检查宿主后端、Provider 绑定、Key 和渠道启用状态，再看看日期与币种筛选。配置看起来正确，不代表请求已经成功；没有经过插件的调用也不会入账。

### “已有请求记录”是不是说渠道不能用了？

不是。这个提示是在保护历史账目，不是在停用渠道，也不是连通性检测。只要渠道启用、凭据和路由有效，就能继续使用。

### 卸载会删除账本吗？

不会。退出 DSH 后运行下面的命令，把 `web` 换成实际 Profile：

```powershell
dsh plugin --profile web remove dsh-web-search-billing
```

卸载不会自动擦除历史数据。
